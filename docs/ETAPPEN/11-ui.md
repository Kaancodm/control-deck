## 1 Ziel

Eine schlanke, serverseitig gerenderte Oberflaeche unter `/ui` fuer den Owner: Liste, Detail mit
Zeitlinie, Anlegen, Blockiert-Ansicht mit manueller Freigabe, Ergebnis-Freigabe, Abbruch, Not-Aus
und Dead-Letter-Liste. Keine Geschaeftslogik in Templates: die UI ruft dieselbe Service-Schicht wie
die API (Vertrag 4 → 11).

## 4 Default-Entscheidungen

| Nr | Entscheidung |
|----|--------------|
| D1 | Jinja2 mit `autoescape=True` (neue Laufzeit-Abhaengigkeit, im PR begruenden: Auto-Escaping gegen XSS, Plan-Leitentscheid 2). Templates in `app/ui/templates/`, Basis-Layout `base.html`. |
| D2 | HTMX als lokale Datei `app/ui/static/vendor/htmx.min.js`, Version festgehalten in `app/ui/static/vendor/VENDOR.md` mit SHA-256; Meta `htmx-config` mit `allowEval: false`, `allowScriptTags: false`, `selfRequestsOnly: true`. Kein CDN, keine externe URL. |
| D3 | CSS nur `app/ui/static/app.css`; kein Inline-Style, kein Inline-Script. Header: `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`. |
| D4 | Zwischen-Login bis Etappe 15: `GET /ui/login` fragt den Owner-Token ab, Vergleich mit `DECK_OWNER_TOKEN` in konstanter Zeit, setzt Cookie `deck_session` (HMAC mit `DECK_SECRET_KEY`, Ablauf 12 h, `HttpOnly`, `SameSite=Strict`, `Secure` ausser Loopback). Alle `/ui`-Routen ausser `/ui/login` und `/ui/static` verlangen die Session. Modul `app/ui/session.py` so bauen, dass Etappe 15 nur den Pruefschritt ersetzt. |
| D5 | CSRF: Token je Session (HMAC aus Session-ID), als verstecktes Feld in jedem Formular und als Header `X-CSRF-Token` fuer HTMX-Posts; fehlend oder falsch → 403, kein Zustandswechsel. |
| D6 | Bindung ueber `DECK_BIND_HOST` (Default Loopback); Warnung im Log, wenn nicht Loopback. Kein Literal im Repo. |
| D7 | Zwei getrennte Freigaben, klar beschriftet: **Start-Freigabe** (`awaiting_approval → queued`) und **Ergebnis-Freigabe** (`review → done`). Ablehnen im Review mit Begruendung und Wahl "naechstes Kettenglied" (`→ queued`) oder "abschliessen" (`→ failed`). |
| D8 | Blockiert-Ansicht: zeigt Scanner-Treffer (Kind, Anzahl, Position), nie Werte; manuelle Freigabe nur mit Begruendung (Pflichtfeld, mindestens 10 Zeichen) → `blocked → queued`, Event mit `actor = owner`, `reason`. |
| D9 | Abbruch: in `awaiting_approval`, `queued` sofort `cancelled`; in `leased`, `running` setzt `cancel_requested` mit Grund (VB-5); Anzeige "Abbruch angefordert" bis der Runner bestaetigt. |
| D10 | Not-Aus: Umschalter im Kopfbereich fuer `settings.paused`, zweiter Bestaetigungsschritt (Dialog mit Wiederholung des Wortes "STOP"), Zustand als Band auf jeder Seite; je Lane `lanes.<lane>.paused` auf der Lane-Zeile. |
| D11 | Formular "Neuer Auftrag": `data_class` sichtbar auf `local_only` vorbelegt; Wechsel auf `cloud_*` zeigt Hinweis und verlangt eine Bestaetigungs-Checkbox; `fallback_chain` als geordnete Auswahl; `policy`-Felder mit Schema-Grenzen; `acceptance` als einfache Zeilen (Typ, Wert); Absenden erzeugt `task.v1` ueber die Service-Schicht (Validierung dort), Fehler werden feldbezogen angezeigt. |
| D12 | Detailseite: Auftrag unveraendert (nur Anzeige), Zustand als Text und Farbe, Zeitlinie aus `events` (Zeit, Trigger, Akteur, Grund, Versuch), Versuchstabelle aus `results`, Ausgabe rueckabgebildet mit Markierung der aufgeloesten Platzhalter (Titel-Attribut "aus Platzhalter"), Link auf `payload.sent.md` ("so hat es den Server verlassen"). |
| D13 | Liste: Filter `state`, `data_class`, `lane`, Suche im Titel; 50 je Seite; Dead-Letter-Liste = `state = failed` mit erschoepfter Kette (Kennzeichen aus Etappe 10) als eigener Reiter. |
| D14 | Payload-Route liefert `text/plain; charset=utf-8` und `nosniff`; Pfad ausschliesslich ueber `app/core/paths.py`. |
| D15 | Responsive ohne Build-Schritt: `meta viewport`, Seitenrand 16 Pixel, Tabellen als Karten unter 600 Pixel, Touch-Ziele mindestens 44 Pixel, keine festen Breiten ueber 360 Pixel, kein horizontales Scrollen. |
| D16 | Tests mit `fastapi.testclient.TestClient` und `html.parser` (Standardbibliothek). Keine Browser-Automatisierung in CI. |

## 5 Umsetzung

### 5.1 Routen

| Methode, Pfad | Zweck | Zustandswechsel |
|---------------|-------|-----------------|
| `GET /ui` | Weiterleitung auf `/ui/tasks` | – |
| `GET, POST /ui/login`, `POST /ui/logout` | Zwischen-Login (D4) | – |
| `GET /ui/tasks` | Liste mit Filtern, Reiter "Dead-Letter" | – |
| `GET, POST /ui/tasks/new` | Formular, Anlegen | `→ awaiting_approval` (oder `queued`, wenn `requires_approval = false`) |
| `GET /ui/tasks/{id}` | Detail, Zeitlinie, Versuche, Ausgabe | – |
| `GET /ui/tasks/{id}/payload/{attempt}` | `payload.sent.md` als Text | – |
| `POST /ui/tasks/{id}/approve-start` | Start-Freigabe | `awaiting_approval → queued` |
| `POST /ui/tasks/{id}/approve-result` | Ergebnis-Freigabe | `review → done` |
| `POST /ui/tasks/{id}/reject` | Ablehnen mit Grund und Ziel | `review → queued` oder `→ failed` |
| `POST /ui/tasks/{id}/unblock` | Freigabe mit Begruendung | `blocked → queued` |
| `POST /ui/tasks/{id}/cancel` | Abbruch | `→ cancelled` oder `cancel_requested` |
| `GET /ui/blocked` | Blockiert-Ansicht | – |
| `POST /ui/settings/paused` | Not-Aus global | `settings.paused` |
| `POST /ui/settings/lanes/{lane}/paused` | Lane pausieren | `settings.lanes.<lane>.paused` |
| `GET /ui/static/...` | CSS, HTMX | – |

HTMX wird nur fuer Teil-Aktualisierungen genutzt (Zeitlinie, Zustandsband); jede Aktion
funktioniert auch ohne JavaScript als normales Formular (Progressive Enhancement).

## 6 Abnahmetests

| Nr | Fall | Erwartet |
|----|------|----------|
| S1 | Titel mit spitzen Klammern und Script-Tag | erscheint escaped, kein Script-Element im DOM |
| S2 | POST ohne CSRF-Token, mit falschem Token | 403, kein Event, kein Zustandswechsel |
| S3 | Zugriff ohne Session | Weiterleitung auf `/ui/login`; falscher Token → 401 ohne Hinweis welcher Teil falsch ist |
| S4 | Sicherheits-Header auf jeder Antwort | CSP, nosniff, Referrer-Policy vorhanden |
| S5 | Templates und CSS enthalten keine externe URL und kein Inline-Script | `grep` auf `http://`, `https://`, `<script>` ohne `src="/ui/static` leer |
| F1 | Formular Default `data_class = local_only`; `cloud_*` ohne Checkbox | Fehlermeldung, kein Task |
| F2 | Anlegen gueltig | Task in `awaiting_approval`, Event `submit`, Detailseite zeigt ihn |
| F3 | Start-Freigabe | `queued`, Event mit `actor = owner` |
| F4 | Ergebnis-Freigabe aus `review` | `done`; aus anderem Zustand → 409 |
| F5 | Ablehnen mit Grund, Ziel "naechstes Glied" und "abschliessen" | `queued` bzw. `failed`, Grund im Event |
| F6 | Blockiert-Ansicht: Freigabe ohne Grund | abgelehnt; mit Grund → `queued`, Event `unblock` |
| F7 | Abbruch in `queued` und in `running` | `cancelled` bzw. `cancel_requested = true` |
| F8 | Not-Aus ohne Bestaetigungswort | kein Wechsel; mit Wort → `settings.paused = true`, Band sichtbar auf allen Seiten |
| F9 | Filter `state`, `data_class`, `lane`; Dead-Letter-Reiter | Treffermengen stimmen mit DB ueberein |
| F10 | Detail zeigt Zeitlinie mit Akteur und Grund; Ausgabe mit markierten Platzhaltern; Payload-Link liefert `text/plain` und `nosniff` | geprueft |
| F11 | Zustandsanzeige zeigt alle zehn Zustaende als Text (nicht nur Farbe) | Snapshot-Test |
| R1 | Responsive-Basis: `meta viewport` vorhanden; `app.css` ohne feste Breite ueber 360 Pixel (`grep`) | geprueft |
| M1 | Smoke-Test (Owner, Handy und Desktop): Auftrag anlegen → Start-Freigabe → Lauf gegen Stub oder Ollama → Ergebnis-Freigabe → `done`; Trap-Auftrag → Blockiert-Ansicht → Freigabe mit Grund; Not-Aus stoppt den Pull | alles ohne CLI, Protokoll im PR |

## 8 Blocker-Regel

Stoppen und melden, wenn: `review`, `done` oder der Uebergang `blocked → queued` auf `main` fehlen
(VB-3); PR #5 nicht gemergt ist; `settings` oder `lane_status` fehlen (Etappen 8, 9); Etappe 10 kein
Kennzeichen fuer erschoepfte Ketten liefert (dann Dead-Letter-Reiter als `state = failed` bauen und
im PR vermerken, kein Stopp); die Service-Schicht nur ueber HTTP erreichbar waere.

## 9 Risiken und Gegenmassnahmen

| Risiko | Gegenmassnahme |
|--------|----------------|
| UI ohne echten Login erreichbar | Zwischen-Login D4, Loopback-Default, Etappe 15 folgt |
| Rohdaten in der Anzeige (Map-Werte) | Rueckabbildung nur in der Ausgabeansicht, Blockiert-Ansicht zeigt nie Werte |
| Fehlklick auf Not-Aus oder Freigabe | Bestaetigungsschritt, Begruendungspflicht, Events |
| XSS ueber Auftragsinhalte | Auto-Escaping, CSP ohne Inline, HTMX-Konfiguration ohne Eval |
| Doppelte Logik in API und UI | gemeinsame Service-Schicht, Tests beider Pfade |
